# Utopia 重构之路：从 LibreTV 到 TVBox

> 2026-11 · [jiangrenbielang](https://github.com/jiangrenbielang) · [仓库](https://github.com/jiangrenbielang/utopia) · [下载 v0.1.0](https://github.com/jiangrenbielang/utopia/releases)

2026年10月25日，我在B站看网课时苦于每次都要自己手动调进度，便想着能不能做一个有记忆功能的播放器，于是有了 Utopia。它的播放内核与聚合能力最初来自 [LibreTV](https://github.com/LibreSpark/LibreTV)——那时我在它上面加了计时、统计和课程库，跑得也不错。

但用了一个月，我越来越清楚地感觉到：**LibreTV 的形态和我要的不一样**。它是为浏览器聚合搜索设计的，而我需要的是一个每天打开、看网课、自动记时长的「学习台」，并且我大部分时间在 Windows 桌面上。于是一次大重构开始了。

## 一、数据入口：从 LibreTV 源列表改为 TVBox 配置地址

LibreTV 的用法是「维护一堆源 + Web 端配置」：访问密码、`DEFAULT_*` 环境变量、Docker 配置项……这些在个人使用场景里全是负担。

重构后，Utopia 的数据入口改成 **TVBox「配置地址」驱动**——填一份接口 JSON，点播站点、解析线路、壁纸就全带出来了：

- 一条地址完成导入，多仓库配置（`urls:[...]`）自动跟随；
- 新增分类浏览页，按站点分类翻页找课；
- 播放页集成解析线路面板，一条线路不行就换下一条；
- 依赖 Spider 引擎（jar/dex）的站点会被跳过并说明原因——那是 Android 原生生态，Web 客户端跑不了，宁可明确告知也不假装能用。

界面也跟着换血：LibreTV 的深蓝黑霓虹风整体改为 **TVBox 风格**——中性深色、海报网格、顶部分类 tab。学习计时、倒计时、统计图表、课程库这些 Utopia 自己的东西全部保留。

**随之删除的**：LibreTV 整套 Web 端配置（访问密码、`.env`、Docker 配置项）。个人工具不需要这些。

## 二、做减法：删掉 iframe 嵌入与本地高清播放

这次重构里我删掉了两块「历史包袱」：

**iframe 嵌入播放。** 早期课程章节支持粘贴 B 站 iframe 代码，但 iframe 是跨域页面，播放器读不到播放状态，计时只能按「页面可见时长」近似。现在统一走 TVBox 式的**直链 + 解析线路**：m3u8/mp4 直接播、按真实播放进度计时、能拖动进度条也能记住看到哪。播放内核只剩一条清晰的路径，不再维护两套计时口径。

**companion 伴生程序 + mpv 本地高清播放。** 为了 1080P 高清，之前在客户端旁边跑一个 Python 伴生程序，再拉起独立的 mpv 窗口。它带来一串代价：用户要装 Python 和 mpv、构建要 PyInstaller 打包、mpv 是独立窗口嵌不进页面、关闭后才同步学习记录。**整套删掉**。播放全部回到应用内的 ArtPlayer + hls.js，学习体验从「弹个窗口、关了才记时长」变成「就在学习台里看、看着就计时」。

安装包从 **160.5 MB 减到 116.8 MB**，构建不再需要 Python、mpv、companion 目录——任何人 clone 下来就能构建。

## 三、Electron 桌面客户端：一份服务端逻辑，两个宿主

重构的另一半是**把学习台做成桌面应用**。

架构上最有意思的决定是把服务端抽成了**宿主无关的服务核**（`src/server/`）：同一份逻辑，部署到 Web 时是 Next.js 的 Route Handler（`src/app/api/**` 只是薄壳），跑在桌面时是 Electron 主进程内建的 Node `http.Server`。改一处，两端同步生效，不会出现「网页上好了、桌面端还是旧行为」的漂移。

桌面客户端的形态：

- 主进程拉起**内建本地数据层**：静态导出的页面 + 编译好的服务核，监听 `127.0.0.1:3210`，不再有 Next.js 长驻服务；
- 去掉了**应用菜单栏**，界面干净——`Ctrl+,` 打开设置、`F11` 全屏、`Ctrl+=/-/0` 缩放；
- 渲染层日志转发到 `desktop.log`，错误页能展开技术细节，出问题不再靠猜；
- 网盘令牌、内网放行这类敏感配置只留在主进程/服务端，页面拿不到。

顺带把播放器里两个陈年 bug 修了：一是播放器曾把**所有**地址硬编码按 m3u8 塞给 hls.js，mp4 直链永远播不出来（现在按地址类型分流 HLS/原生）；二是代理给整个响应流挂了 8 秒超时，185MB 的网课播到第 8 秒必断、播放器反复重连——表现为「加载极慢」（现在只对等响应头限时）。

## 四、玻璃化界面与壁纸

最后是这轮重构里最「看得见」的部分：**壁纸系统 + 玻璃化界面**。

**壁纸**有三种来源可切换：跟随 TVBox 配置自带的壁纸、导入本地图片、或关闭。本地图片存 IndexedDB（单张上限 12MB），压暗程度和填充方式（铺满裁切 / 完整留边）都可调。

**玻璃化**只在有壁纸时生效：卡片、输入框、顶栏变成半透明 + `backdrop-filter` 毛玻璃，壁纸透出来但文字始终落在一个稳定的颜色上。这里踩过一个真实的坑：浅色主题下近黑文字压在偏暗的照片上会糊成一片，零散改几个字色是补不完的——最终方案是壁纸模式下**整套调色板强制切到深色玻璃 HUD**（白字 + 蓝强调色），不管系统主题、不管壁纸明暗，对比度都稳定。关掉壁纸，界面原样回到实色。
